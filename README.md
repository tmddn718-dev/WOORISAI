# 우리사이 (WOORISAI)

> 함께한 순간을, 우리만의 이야기로.

함께한 사람만 초대해 하나의 추억을 같이 완성하고, 시간이 흐른 뒤 사람·장소·시간을 통해 다시 발견하는 **프라이빗 공동 추억 기록 서비스**입니다.

```bash
npm start   # http://localhost:3000  (Node 24+, 외부 의존성 없음)
npm test    # 권한·삭제 시나리오 테스트
```

데이터는 `data/`(SQLite + 사진)에 저장됩니다. 계정 두 개를 만들어 서로 연결하면 공동 추억 흐름을 체험할 수 있습니다.

## 1. 제품 요약 (통합 PRD §1–2)

사람들은 메신저에서 약속을 잡고, 각자 사진을 찍고, 정산 앱에서 비용을 나누고, 사진 앱에서 과거를 찾습니다. 한 번의 만남이 여러 서비스로 흩어져 그날의 맥락과 공동의 이야기가 남지 않습니다. 우리사이는 **약속 전 – 만남 중 – 만남 후 – 시간이 흐른 뒤**를 하나의 관계 맥락으로 연결합니다.

```text
사람 선택 → 공동 게시물에 각자 사진·글 추가 → 사람·장소·시간으로 축적 → 공동 회상으로 재발견
```

| 가치 | 제품 약속 |
|---|---|
| 사적인 공유 | 초대한 사람만 보고 기여하는 기본 비공개 공간 |
| 공동 소유감 | 한 명의 게시물이 아니라 참여자가 함께 완성하는 기록 |
| 관계 유연성 | 친구·가족·연인을 같은 구조로, 사람 중심 구성 |
| 생활 도구 | 모임, 참석응답, 정산을 추억 생성 흐름과 연결 |
| 장기적 가치 | 사진 마커 지도, 1년 전 오늘로 기록을 재발견 |
| 감정적 안전 | 보고 싶지 않은 사람·추억은 추천에서 제외 |

**비목표:** 공개 피드·팔로우·광고, 실시간 위치 공유, 송금·보관·대출, 얼굴 인식 기반 추정, 관계 유형별 별도 권한 체계.

### 구조 원칙

> 그룹은 편의를 위한 묶음, 모임은 특정 시점의 약속, 공동 게시물은 실제로 공유하기로 한 추억이다.

- 그룹 없이 사람을 골라 모임·공동 게시물을 만들 수 있습니다.
- 같은 그룹의 미초대 멤버는 해당 게시물을 볼 수 없습니다.
- 그룹 소속, 실제 참석, 게시물 열람권한은 **서로 다른 데이터**입니다. 하나를 다른 하나의 근거로 추정하지 않습니다.
- 관계 유형(친구/가족/연인)은 개인화 힌트일 뿐 권한을 확장하지 않습니다.

## 3. 정보 구조

| 탭 | 역할 |

| 홈 | 최근 공동 게시물, 초대, 예정 약속, 회상 카드, `추억 만들기` |

## 4. 권한 모델 (통합 PRD §7)

게시물 열람권한은 **`PostMember`만** 결정합니다.

| 행동 | 관리자 | 기여자 | 같은 그룹 미초대자 |
|---|:---:|:---:|:---:|
| 게시물 열람 | O | O | X |
| 자신의 기여물 추가/삭제 | O | O | X |
| 타인의 기여물 삭제 | 신고 | 신고 | X |
| 멤버 초대·정보 수정 | O | X | X |
| 나가기 | 관리자 이전 필요 | O | 해당 없음 |

**불변식**

1. 서버는 화면 노출과 무관하게 요청마다 객체 단위로 권한을 검사합니다.
2. 그룹 멤버십·RSVP·실제 참석은 `PostMember`를 자동 생성하지 않습니다.
3. 지도·검색·회상 등 파생 뷰는 원본의 현재 권한보다 넓게 노출되지 않습니다.
4. 차단 즉시 신규 초대·댓글·알림이 중단되고, 상대의 기여물은 내 화면에서 숨겨집니다.
5. 정산 참여자가 아니면 같은 모임·게시물 멤버라도 금액을 볼 수 없습니다.
6. 사진은 요청마다 로그인과 현재 멤버 여부를 확인한 뒤 내려주며, 권한이 사라지면 즉시 접근할 수 없습니다.

이 불변식은 `test.js`에서 자동으로 검증합니다 (미초대 그룹 멤버 접근 차단, 수락 전 비노출, 나간 뒤 지도·딥링크·저장 목록 제거, 정산 비노출, 차단 후 초대 불가, 삭제 시 원본 파일 제거 등).

## 5. 프라이버시·안전 기본값 (통합 PRD §11)

- 모든 게시물·모임·정산·지도는 기본 비공개이며 외부 공유 링크는 제공하지 않습니다.
- 사진은 JPEG만 받고 **EXIF(GPS 포함)는 업로드 시 제거**합니다. 클라이언트에서 다시 인코딩한 뒤 서버가 한 번 더 제거합니다.
- 실시간 위치·백그라운드 추적은 제공하지 않으며, 장소는 사용자가 직접 입력합니다.
- 초대 링크는 1회용이고 7일 후 만료, 언제든 회수할 수 있습니다.
- 회상은 별도 옵트인이며 기능을 꺼도 원본 기록은 삭제되지 않습니다. 사람·추억 단위로 추천에서 제외할 수 있습니다.
- 계정 탈퇴 시 남은 공동 기록은 `탈퇴한 사용자`로 익명화되며, 원하면 내가 올린 사진·글도 함께 삭제됩니다.
- 로그인 시도 제한, CSRF 방어(`SameSite=Strict` + 커스텀 헤더), CSP 헤더를 적용했습니다.

## 6. 데이터 모델 (통합 PRD §14)

```text
User ──< GroupMember >── Group
  ├──< MeetupParticipant >── Meetup ──< Settlement ──< Share
  │                                └── optional ──> MemoryPost
  └──< PostMember >──────── MemoryPost ──< Media / Note(글·댓글) / Reaction
                                       └── Place(정밀도) / PostLog
```

반드시 분리하는 필드: `group_member` / `post_member` / `post_participant`, `rsvp` / `attended`, 장소의 저장값 / 표시 정밀도, 삭제 / 개인 숨김 / 운영 제한, `settlement_participant` / `meetup_participant`.

## 간편가입 설정

제공자 앱을 만든 뒤 환경변수를 설정하면 해당 버튼이 켜져요. 설정하지 않은 제공자는 `준비 중`으로 표시돼요. 리디렉션 URI는 `<BASE_URL>/api/oauth/<kakao|google|naver>/callback`으로 등록하세요.

```bash
BASE_URL=https://example.com \
KAKAO_CLIENT_ID=... KAKAO_CLIENT_SECRET=... \
GOOGLE_CLIENT_ID=... GOOGLE_CLIENT_SECRET=... \
NAVER_CLIENT_ID=... NAVER_CLIENT_SECRET=... \
npm start
```

제공자의 계정 번호만 저장하고 이메일·토큰은 저장하지 않아요. 가입 화면의 간편가입 버튼은 공식 로고가 아닌 글자 마크이므로 출시 전 각 제공자의 버튼 가이드에 맞춰 교체해야 해요.
