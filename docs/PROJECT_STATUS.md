## 1. 프로젝트 목적과 핵심 사용자 경험

**목적:** 함께한 사람만 초대해 하나의 추억을 같이 완성하고, 시간이 흐른 뒤 사람·장소·시간으로 다시 발견하는 **프라이빗 공동 추억 기록 서비스**다. 슬로건은 "함께한 순간을, 우리만의 이야기로."

**핵심 경험**
1. 사진 한 장이나 짧은 이야기로 추억을 남기고, 함께한 사람을 초대한다.
2. 초대를 **수락한 사람만** 보고, 각자 사진과 이야기를 더한다.
3. 지역을 연결한 추억은 발자국(지역별 기록)에 쌓이고, 달력과 목록으로 다시 찾는다.
4. 약속은 추억을 만들기 위한 **보조 기능**이다. 약속 없이도 바로 추억을 만들 수 있고, 약속을 만든 것만으로 추억이나 발자국을 자동 생성하지 않는다.

**권한의 원칙(PRD §7):** 게시물 열람 권한은 게시물 멤버(초대 수락자)만 결정한다. 그룹, 약속 초대, 참석 응답은 권한이 아니다.

## 5. 추억 만들기와 사진 선택 흐름 (B, 본체)

1. **진입:** 하단 `만들기` 탭 또는 홈의 새 추억 만들기 → 시작 방식 선택(`사진으로 시작하기` / `이야기로 시작하기`). 약속 없이 시작한다 (확인함).
2. **사진 고르기:** 샘플 사진 8장 격자와 `기기에서` 칸이 한 줄에 있다. 별도의 "데모 앨범" 화면이 아니라 이 격자가 데모 앨범 역할을 한다.
   - 여러 장 선택, 선택 순서 번호, "첫 사진이 대표 사진" 안내 (확인함, 3장 선택)
   - `기기에서`: `<input type="file" accept="image/*" multiple>`로 기기 사진을 받는다(코드 확인). 받은 사진은 `URL.createObjectURL`로 **브라우저 메모리에만** 두고 새로고침하면 사라진다. **실제 파일 선택 창은 열어 보지 못했다.**
   - 선택 해제: 코드에 `선택 해제` 처리가 있다. 내 확인 시도는 결과가 모호해서 **동작은 확정하지 못했다.**
   - 사진 삭제·추가(저장 후): **미확인.**
3. **입력:** 제목(필수), 날짜, 이야기(선택), 함께한 사람(칩), 지역(선택, §9의 수정 참고), 장소(지역을 고르면 나타나는 선택 칸). 임시 저장 표시가 있다.
4. **저장 후:** 상세로 이동하고 최근 추억 맨 앞에 "방금 남긴 추억"으로 놓인다 (확인함).
5. **이야기만으로 저장:** 사진 0장으로 저장된다 (확인함). 같이 한 사람이 없으면 "혼자 남긴 추억"으로 표시한다.
6. **권한:** 저장 안내 문구는 "초대한 사람만 볼 수 있어요", 초대는 수락한 사람만 본다고 안내한다.

## 6. 약속 만들기와 추억 연결 흐름 (B, 본체)

**약속 만들기** (확인함): 홈 `새 약속 만들기` → 제목·날짜·시간(필수, 비면 "입력해 주세요"), 장소·초대·메모(선택) → 저장하면 약속 상세, 홈 "다가오는 약속"과 달력에 반영. 초대한 사람은 `초대 대기`로 보이고 "초대에 답하기 전에는 참석으로 표시하지 않아요" 안내가 있다. 빈 상태(첫 사용자)에서도 만들어진다 (확인함, 달력 "추억 1개 · 약속 1개").

**참석 상태:** 초대 대기 / 참석 / 미정 / 불참. `초대받은 사람 시점으로 보기`(데모)로 시점을 바꿔 참석·불참을 바꾸면 참석 현황이 갱신된다 (확인함). 약속 수정·취소, 일정 변경 안내(`변경됨` 배지)는 **코드와 갤러리 화면에 있으나 눌러 보지는 않았다.**

**상태별 CTA**
- 지난 약속, 연결된 추억 없음: `이 약속을 추억으로 남기기` (확인함)
- 추억이 연결된 약속: `함께한 추억 보기` (확인함, 홈의 "지난 약속을 추억으로 남길까요?" 안내도 사라짐)
- 미래 약속: 참석 여부 확인·변경 (확인함)
- 취소된 약속(취소 표시, 추억 CTA 숨김): **갤러리 화면(`planCancel`)이 렌더링되는 것만 확인했고 동작은 눌러 보지 않았다.**

**약속에서 추억 만들기** (확인함): 새 추억 화면으로 이동하며 제목·날짜·장소·함께한 사람 후보가 채워진다. 후보는 **참석한 사람만**(불참한 사람은 빠짐)이고, 사용자가 고쳐서 실제 함께한 사람만 초대한다. 지역은 채우지 않고 직접 고르게 한다. 약속의 참석 상태만으로 추억 접근 권한을 주지 않는다는 안내 문구가 있다.

**연결 규칙:** 약속과 추억은 따로 저장되고, 추억을 저장할 때만 약속에 `memId`로 연결된다(코드 확인).

## 7. 사진 스와이프 및 참여자별 갤러리 (B, 본체)

- **전체 사진 스와이프:** 추억 상세의 상단 갤러리가 `scroll-snap-type: x mandatory`이고 `1 / 3 → 2 / 3 → 3 / 3`처럼 위치가 바뀐다 (확인함, 3장짜리 추억). **마우스·터치 드래그가 아니라 스크롤 값을 바꿔서 시험했다.**
- **`+N` 오버레이:** 상세 화면 텍스트에서 `+숫자`가 나오지 않았고, 코드에 `+N`/`moreCount` 처리가 없다 (확인함).
- **참여자별 갤러리:** 참여자마다 별도 갤러리를 가진다(`contribs`, 라벨 "○○님이 남긴 사진", 각각 스크롤 위치 추적). 코드 확인. 화면으로 하나씩 확인하지는 않았다.
- **내 사진과 이야기 더하기:** 시트로 기존 추억에 기여하는 기능이 코드에 있다. 비로그인에서는 로그인 안내로 막힌다(§8). 동작은 **미확인.**
- **전체 화면 사진 뷰어:** 확대·이동 상태(`scale`, `tx`, `ty`)가 있다(코드 확인). 확대·닫으면 위치 유지는 **미확인.**
- **샘플 사진은 Unsplash 주소**에서 받는다. 인터넷이 없으면 사진이 숨겨진다(코드가 로드 실패한 이미지를 숨김).

## 8. 접근 권한과 비로그인 둘러보기

**실제 서비스(A):** 열람 권한은 서버가 `post_members`(수락)만으로 결정한다. 지도·목록·오늘·저장 같은 파생 화면은 현재 권한의 교집합만 보이고, 정산 금액은 정산 참여자에게만 보인다. 사진은 요청마다 로그인과 멤버 여부를 확인해서 내려준다. 이 규칙은 `test.js`가 검증한다(마지막 통과 11-10).

**프로토타입(B, 서버 없음):** 권한 제어는 **시뮬레이션**이다.
- **둘러보기(비로그인) 모드** (코드 확인, 첫 진입 화면은 갤러리에서 렌더링 확인): 샘플 추억 5개(`GUEST_IDS`)만 보이고 사람 이름은 `친구 A/B/C`로 바뀐다. 약속 섹션은 숨겨진다.
- **로그인이 필요한 행동**(`gate`): 추억 만들기, 사진·이야기 더하기, 참여자 보기, 발자국의 "함께한" 보기. 누르면 이유와 함께 로그인 안내가 뜬다.
- 로그인 후 **원래 하던 행동으로 복귀**하는 구조(`intent`)가 코드에 있고 화면 설명에도 있다. **복귀 동작은 직접 확인하지 못했다.**
- 로그아웃하면 둘러보기 모드로 돌아간다(코드 확인).
- 데모 로그인은 어떤 값을 넣어도 `서연` 계정으로 들어간다. 실제 인증·알림·권한 제어는 없다.

**발자국 규칙:** 사용자가 **지역을 연결한 추억만** 반영한다(확인함). 약속의 장소만 입력했다고 방문한 지역이 되지 않는다. 지역 없이 저장한 추억은 발자국의 지역 수·추억 수에 들어가지 않는다.
